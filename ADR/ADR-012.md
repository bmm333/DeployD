# ADR-010: Reproducible evaluation and auditability

## Context

ADR-007 defines the hybrid retrieval design and its signal weights. It does
not define how those signals, the topology-aware gate, operations metrics, or
the LLM boundary are evaluated without introducing label leakage.

The evaluation must distinguish measured results from unavailable results and
must use the same live event path as the application.

## Decision

The reproducible evaluation is implemented by
[`experiments/run_all.py`](../experiments/run_all.py) and writes its outputs
to [`experiments/results/`](../experiments/results/).

Retrieval structural context is always produced through:

`raw events -> HttpEventAdapter -> CorrelateEventsUseCase -> IncidentGraph -> chain/components`

The expected runbook ID is used only as an evaluation label. Label
`causal_chain` and `affected_components` values are never used as retrieval
inputs. This prevents label leakage.

The runner evaluates:

- semantic, BM25, causal, component and all-signal retrieval variants;
- recall@1, recall@3 and MRR;
- query-level rankings, signal provenance and non-evaluable cases;
- cosine similarity versus the previous L2 distance on the same query set;
- gate thresholds from 0.30 through 0.80 with a documented 0.05 step;
- FULL, CHAIN_ONLY, NO_TRIGGER and false-causality scenarios;
- correlation/retrieval latency and embedding cold-start measurements.

The random recall@3 baseline for the 10-runbook corpus is recorded in
`retrieval.json` as `k / number_of_runbooks`, not inferred from the measured
system result.

## LLM availability

LLM evaluation is conditional on `GROQ_API_KEY`. When the key is absent,
`llm.json` and `llm.md` explicitly report `status=skipped`; no mock or
fabricated citation, groundedness, token or cost result is emitted. Retrieval,
gate and operations evaluation do not require an API key.

When provider-backed evaluation is unavailable, its metrics are represented as
unavailable rather than zero. This applies to provider latency, token usage,
cost, citation validity, prompt-injection resistance and poisoned-runbook
behaviour.

## Results and interpretation

All numerical claims belong to the generated files under
`experiments/results/`. The current corpus contains 10 runbooks and the
retrieval dataset is intentionally small, so the results are evidence for the
implemented fixtures, not a general production benchmark.

The former claim that a component weight above 0.25 degrades separation is not
retained as an established result. The current experiment does not contain a
controlled weight sweep proving it; it remains a possible future hypothesis.

## Consequences

- Evaluation can be regenerated with:

  ```text
  python -m experiments.run_all --seed 20261009
  ```

- JSON files are machine-readable and Markdown files provide an audit view.
- Re-running with the same seed is deterministic for non-timing content.
- Timing and environment values remain measured run metadata and may vary
  between executions.
- Small datasets, limited hard negatives and rule-dependent structural
  context remain explicit limitations.

## Status

Accepted. This ADR supplements ADR-007; it does not replace or rewrite the
retrieval design decision recorded there.
