# ADR-013: Human-in-the-Loop Decisions

**Date:** 2026-10-11
**Status:** Accepted

## Context

DeployD's rule is "the system suggests, engineers approve", but until DID-38 approval was only a banner under the diagnosis. Nothing recorded whether the engineer agreed. A rejection never reached the agent.

## Decision

Every Tier-3 answer is reviewed by an engineer, and the review is a recorded fact.

- **Three decisions** (`HumanDecision`, domain):
  - **ACCEPT**;
  - **REJECT**, which needs a reason;
  - **AMEND**, which needs the edited recommendation.

  The record copies the answer under review: root cause, recommendation, cited runbooks, model and prompt version. The audit trail therefore does not depend on the chat history.
- **Stored on the incident** (`Incident.decisions`, the `decisions` column in SQLite): only the open incident takes decisions. They stay with it after it is resolved, and are shown by `GET /api/v1/incidents/{id}`.
- **Rejection closes the loop.** The reason goes to the agent on the same session, framed as unverified engineer input like any follow-up. The revised answer becomes the next version (v2, v3, …) and is reviewed again, until it is approved or the session runs out of turns.
- **Nothing is executed.** Approving only records the decision. Command execution stays out of scope (AGENTS.md): the same read-only guarantee as the agent's tools.

API: `POST /api/v1/incidents/{id}/decision`.
- `/state` exposes the answer under review (`review`) and the decision trace the latest decision.
- The live UI shows Approve / Reject / Edit & approve under the answer awaiting review.

## Consequences

- Each incident can show who approved which recommendation, on which evidence, and from which model and prompt version.
- **A revision is a follow-up turn** (prose with confidence and citations), not a fresh structured diagnosis. Its "recommendation" is the revised answer as written.
- **The engineer is not authenticated**: their name is typed in the UI. That is enough for a single-tenant proof of concept. In a real deployment it would come from SSO.
