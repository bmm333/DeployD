# ADR-010: Live Investigation Use Case

**Date:** 2026-10-07
**Status:** Accepted

## Context

The live API (`deployd/entrypoints/api.py`) built the investigation itself: longest causal chain, rules along it, FSM state, retrieval query, orchestrator call and fail-closed handling (`_run_investigation`, `_longest_chain`, `_chain_rules`, `_fsm_state`). That is application logic in an entrypoint, and `RetrieveCandidates` depended on the concrete `HybridRetriever`.

`BuildInvestigation` (DID-20) offered a second way to build an investigation, with a CRASH_LOOP trigger through `ComponentHealthTracker`, but nothing called it except its own tests: neither the API nor the demos.

## Decision

1. **`LiveInvestigation` use case** (`application/use_cases/live_investigation.py`) owns the steps above and returns a `LiveInvestigationResult` DTO. `api.py` takes a graph snapshot, calls `execute()` and formats the result for the chat and the decision trace.
   - `on_start(component, hops)` is called once the chain is known, so the API can announce the investigation before the slow part (retrieval, agent).
   - `agent_errors` is injected by the composition root: the application layer cannot import Agno or Groq exceptions, yet those are the only ones that may fall back to the deterministic result. Any other exception is a bug and propagates.
2. **`RetrievalPort`** (`application/ports/retrieval_port.py`): `RetrieveCandidates`, `LiveInvestigation` and the API's retrieval stack depend on the port; `HybridRetriever` is only constructed in the composition root.
3. **The trigger stays severity-based**: an investigation starts when the incident graph becomes CRITICAL (a 2+ hop causal chain). The `ComponentHealthTracker` trigger is **not** wired into the live path. When this was decided the FSM never left HEALTHY on live events; DID-43 fixed that, so the tracker now fires on a crash sent over HTTP. Wiring it in still needs one change: an FSM trigger that finds no causal chain must not use up the incident's single investigation.
4. **`BuildInvestigation` is removed** as dead code. The reactive logic it wrapped lives in `ComponentHealthTracker` (domain, covered by `test_tracker.py` and `test_fsm_on_live_events.py`).

## Consequences

- `api.py` keeps only transport, locking and formatting; the investigation can be unit-tested with a stub retriever and agent (`test_live_investigation.py`).
- No `deployd.adapters` import remains under `deployd/application/`.
- A crash that does not produce a 2+ hop causal chain is not investigated automatically.
