# ADR-001: Clean Architecture Layer Boundaries

**Status:** Accepted
**Date:** 2026-10-06

## Context

DeployD performs incident diagnosis on live infrastructure. To keep the safety
boundary explicit and testable the codebase must separate *what the system knows*
from *how it stores and retrieves data* and from *how it exposes behaviour to the
outside world*.

## Decision

The codebase is organised into four concentric layers following Clean Architecture:

```
┌─────────────────────────────────────────────┐
│  Entrypoints  (FastAPI / CLI)               │  ← outermost: speaks HTTP/JSON
├─────────────────────────────────────────────┤
│  Adapters  (incoming / outgoing)            │  ← translate external ↔ domain
├─────────────────────────────────────────────┤
│  Application  (use-cases / orchestrators)   │  ← choreographs domain objects
├─────────────────────────────────────────────┤
│  Domain  (entities / rules / graph)         │  ← innermost: pure Python, no I/O
└─────────────────────────────────────────────┘
```

### Layer responsibilities

| Layer | Package | Allowed imports |
|---|---|---|
| **Domain** | `deployd.domain` | stdlib + pydantic only |
| **Application** | `deployd.application` | domain + stdlib |
| **Adapters** | `deployd.adapters` | application + domain + 3rd-party clients |
| **Infrastructure** | `deployd.infrastructure` | application + domain + stdlib + 3rd-party |
| **Entrypoints** | `deployd.entrypoints` | all layers |

### Enforcement rules

1. **Dependency direction is inward only.** The domain never imports from adapters
   or infrastructure. Violations are caught by the import graph linter.
2. **Ports (Protocols) live in the domain or application layer.** Concrete
   implementations live in infrastructure/adapters and are injected at startup.
3. **DTOs are the sole crossing point at the agent boundary** — see ADR-008.
4. **No remediation logic in any layer below Entrypoints.** All execution of
   production-side effects requires an explicit human approval gate.

## Consequences

- The `domain/` package can be tested without any I/O or network dependency.
- Swapping a persistence adapter (e.g. JSON → SQLite → Postgres) requires no
  change to domain or application code.
- New ingestion channels (log tailing, Kafka, …) are added as adapters without
  touching the core diagnosis pipeline.
