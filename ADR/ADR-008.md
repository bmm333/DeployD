# ADR-005: Investigation Orchestrator and the No-Hallucination Guarantee

## Context

DeployD aims to provide automated remediation for incidents, but we must guarantee that the AI agent never hallucinates a fix when there is insufficient evidence. We need a structural mechanism to enforce this rule before the LLM is ever invoked.

## Decision

We will implement an `InvestigationOrchestrator` at the application layer that acts as the single enforcement point for this guarantee. It will inspect the availability of evidence (from the `IncidentGraph` and `HybridRetriever`) and dispatch the investigation to one of three tiers:

- **Tier 1 (INCONCLUSIVE)**: FSM is healthy, IncidentGraph is empty. No observable data. The orchestrator returns deterministically. The AI agent is NEVER called.
- **Tier 2 (CHAIN_ONLY)**: Causal chain exists, but no historical match above confidence threshold. The chain is surfaced to the engineer. The AI agent is NEVER called, and the remediation summary states no known fix exists. `requires_human_approval` is always True.
- **Tier 3 (FULL)**: Causal chain exists AND strong historical match exists. The AI agent is called to produce a grounded diagnosis. `requires_human_approval` is True.

## Consequences

- **Zero Hallucination Risk by Construction**: By structurally blocking the AI agent in Tiers 1 and 2, DeployD never hallucinates a fix. This document acts as the technical report that backs the "DeployD never hallucinates" claim — this is the actual enforcement point, not just a design intention.
- **Cost Efficiency**: Tiers 1 and 2 incur zero token cost.
- **Honesty**: The system is honest about what it doesn't know, instead of relying on prompt engineering to suppress hallucinations.
