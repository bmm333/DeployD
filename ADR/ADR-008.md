# ADR-008: DTOs as Boundary Contracts

## Context

The system has two distinct computational zones:

1. **Domain zone** — `CoreEvent`, `IncidentGraph`, `GraphNode`, `GraphEdge`,
   `EdgeType`, `Severity`, `CoreEventType`. These objects encode the business
   logic of what happened and carry domain semantics.

2. **Infrastructure zone** — ChromaDB `QueryResult`, collection handles,
   embedding vectors, BM25 hit lists. These encode how data is stored and
   retrieved.

3. **AI agent zone** — Agno detective agents and LLM calls that reason over
   evidence. These must be completely decoupled from both zones above.

Without an explicit boundary the risk is that an agent:
- imports a `CoreEvent` directly, coupling the agent to the domain model;
- calls ChromaDB to fetch extra context, creating an unbounded side-effect
  inside what should be a pure reasoning step;
- returns a result that silently omits evidence citations, making its
  conclusions unauditable.

## Decision

**DTOs (Pydantic models defined in `deployd.application.dtos`) are the sole
contract crossing the agent boundary in both directions.**

The boundary works as follows:

```
Domain (CoreEvent, IncidentGraph)
    │
    ▼  (EventMapper / GraphMapper)
    │  ← only crossing point allowed to touch domain objects
    ▼
DTO territory (EventDTO, ComponentDependencyDTO, EvidenceDTO, RetrievedEvidence …)
    │
    ▼  (InvestigationOrchestrator.build_investigation_request)
InvestigationRequest ──► AI Agent ──► DiagnosisResult
                                           │
                         (InvestigationOrchestrator.validate_diagnosis_result)
                                           │
                                           ▼
                                    Application / Domain
```

## Specific Rules

### Input Contracts
- Agents accept **only** `DiagnosisRequest` or `InvestigationRequest`.
- No `CoreEvent`, `IncidentGraph`, ORM model, or ChromaDB type may be passed
  to an agent, directly or embedded inside another object.
- All context must be materialised by the Application Mapper **before** the
  boundary is crossed. The agent must not perform any active DB queries.

### Output Contracts
- Agents return **only** `DiagnosisResult`.
- Every claim in `root_cause_explanation` must be backed by at least one
  `EvidenceReference` in `evidence_references` (enforced by `min_length=1`).
- Claims that cannot be backed by evidence are placed in `unsupported_claims`
  so the orchestrator can treat them as speculative rather than silently
  trusting them.

### Evidence Handling
- Agents receive `list[EvidenceDTO]` (live evidence) and
  `list[RetrievedEvidence]` (historical RAG results).
- Agents may identify gaps and return them as `list[MissingEvidence]`.
- The orchestrator schedules further collection passes or escalates to a human.

### Remediation Rules
- In `RemediationRecommendation`, when `requires_human_approval = True` the
  `risk_level` **MUST** be `HIGH` or `CRITICAL`.
- The `InvestigationOrchestrator.validate_diagnosis_result` method enforces
  this rule and raises `BoundaryViolationError` if violated.

### Traceability
- Every assertion in a `DiagnosisResult` must reference at least one
  `EvidenceReference`. The orchestrator enforces `len(evidence_references) >= 1`
  as a defence-in-depth check in addition to the DTO constraint.

## Consequences

### Positive
- **Immutability**: All DTO models use `model_config = ConfigDict(frozen=True)`.
  Facts cannot be mutated after construction.
- **Strict validation**: All confidence/score fields (`semantic_score`,
  `causal_score`, `final_score`, `confidence`, …) are validated as
  `float in [0.0, 1.0]` via Pydantic `ge`/`le` constraints.
- **Security & decoupling**: No ChromaDB internal type (Documents,
  QueryResult, …) leaks beyond the mapper layer.
- **Auditability**: Every agent assertion is traceable to a source incident
  via `EvidenceReference`; unsupported claims are explicitly segregated.
- **Testability**: Mappers and orchestrator validation rules are unit-testable
  without running any LLM or vector store.

### Negative / Trade-offs
- Introducing the mapper layer adds a translation step for every domain object
  that must cross the boundary. This is intentional overhead.
- If a new domain field is added, the mapper must be updated explicitly —
  there is no automatic pass-through. This is a feature, not a bug.

# ADR-005: Investigation Orchestrator and the No-Hallucination Guarantee

## Context

DeployD aims to provide automated remediation for incidents, but we must guarantee that the AI agent never hallucinates a fix when there is insufficient evidence. We need a structural mechanism to enforce this rule before the LLM is ever invoked.

## Decision

We will implement an `InvestigationOrchestrator` at the application layer that acts as the single enforcement point for this guarantee. It will inspect the availability of evidence (from the `IncidentGraph` and `HybridRetriever`) and dispatch the investigation to one of three tiers:

- **Tier 1 (INCONCLUSIVE)**: FSM is healthy, IncidentGraph is empty. No observable data. The orchestrator returns deterministically. The AI agent is NEVER called.
- **Tier 2 (CHAIN_ONLY)**: Causal chain exists, but no historical match above confidence threshold. The chain is surfaced to the engineer. The AI agent is NEVER called, and the remediation summary states no known fix exists. `requires_human_approval` is always True.
- **Tier 3 (FULL)**: Causal chain exists AND strong historical match exists. The AI agent is called to produce a grounded diagnosis. `requires_human_approval` is True.

## Consequences

- **Zero Hallucination Risk by Construction**: By structurally blocking the AI agent in Tiers 1 and 2, DeployD never hallucinates a fix. This document acts as the technical report that backs the "DeployD never hallucinates" claim — this is the actual enforcement point, not just a design intention.
- **Cost Efficiency**: Tiers 1 and 2 incur zero token cost.
- **Honesty**: The system is honest about what it doesn't know, instead of relying on prompt engineering to suppress hallucinations.
