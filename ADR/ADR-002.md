# ADR-002: Core Domain Event Model (`CoreEvent`)

**Status:** Accepted
**Date:** 2026-10-06

## Context

Every adapter (HTTP ingest, log scraper, cloud-watch poller, simulator) produces
raw signals in different formats. Before signals can feed the incident graph or the
process-health FSM they must be normalised into a single canonical representation
that the domain can reason about without knowing which adapter produced it.

## Decision

**`CoreEvent` (defined in `deployd.domain.entities.core_event`) is the canonical,
immutable fact record for every observable signal in the system.**

```python
class CoreEvent(BaseModel):
    model_config = ConfigDict(frozen=True)   # immutable fact

    event_id:    uuid.UUID        # globally unique identity
    event_type:  CoreEventType    # enumerated signal type
    severity:    Severity         # impact classification
    timestamp:   datetime         # UTC, timezone-aware
    source:      str              # originating component name
    description: str              # human-readable summary
    metadata:    dict[str, Any]   # adapter-specific payload
```

### Design rules

1. **Immutability.** `CoreEvent` is `frozen=True`. Once created it is never
   mutated; new observations produce new events.
2. **UTC timestamps.** `timestamp` must be timezone-aware UTC; the validator
   rejects naive datetimes and converts non-UTC offsets.
3. **Typed vocabulary.** `CoreEventType` is a closed `str` enum. Adding a new
   signal type requires an explicit enum member — silent fall-throughs are not
   possible.
4. **Adapter agnosticism.** Adapters translate their raw format into `CoreEvent`
   before handing off to the domain. The domain never sees raw logs or metrics.
5. **Extensibility via `metadata`.** Adapter-specific fields that have no
   domain-level meaning live in `metadata` so the core schema stays stable.

### Type vocabulary (`CoreEventType`)

| Value | Meaning |
|---|---|
| `PROCESS_CRASH` | A supervised process exited unexpectedly |
| `MEMORY_SPIKE` | Resident set size exceeded threshold |
| `CPU_SPIKE` | CPU utilisation exceeded threshold |
| `DEPLOY_STARTED` / `DEPLOY_COMPLETED` / `DEPLOY_FAILED` | Deployment lifecycle |
| `CONFIG_CHANGE` | A configuration file or parameter changed |
| `DEPENDENCY_FAILURE` | An upstream dependency became unavailable |
| `HEALTH_CHECK_FAILED` | A readiness/liveness probe returned non-OK |
| `RESTART` | A supervised process was restarted by the process manager |
| `CUSTOM` | Escape hatch for simulation and testing |

## Consequences

- All domain logic (causal engine, detection rules, FSM) operates exclusively on
  `CoreEvent`; no adapter type leaks into the domain.
- `EventMapper` (application layer) converts `CoreEvent` → `EventDTO` when
  crossing the agent boundary (see ADR-008).
- The closed enum makes invalid event types a schema error, not a runtime
  surprise.
